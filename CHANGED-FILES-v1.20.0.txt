INKAMNET CONTROL CENTER — PATCH v1.20.0
==========================================
Tanggal: 2026-08-18
Paket ini berisi SELURUH file yang berubah (kode utuh, bukan potongan) untuk

CARA PAKAI
----------
1. Backup dulu folder project & database Anda.
2. Extract isi zip ini ke root folder project (struktur folder sama persis:
   routes/, services/, views/, public/, scripts/, app.js, package.json).
   Timpa (overwrite) file yang sudah ada.
3. Jalankan `npm install` bila diperlukan (tidak ada dependency baru yang
   ditambahkan pada patch ini).
4. Restart aplikasi (pm2 restart / node app.js).
5. Hard-refresh browser (Ctrl+Shift+R) agar app.css & app.js versi baru ter-load.

SECTION 4 — Sistem Arsip vs Hapus Permanen & Restore  [PELANGGAN: SELESAI,
                                                        LAINNYA: BELUM]
  Sudah diimplementasikan PENUH untuk PELANGGAN:
    - Kolom baru `archived_at` (timestamp) dipakai sebagai status arsip murni,
      terpisah dari status bisnis pelanggan (active/suspended/terminated) —
      supaya riwayat tagihan/kas tidak pernah berubah hanya karena diarsipkan.
    - Modal pilihan hapus (shared, dipakai lewat atribut data-delete-choice di
      views/partials/layout.ejs + logic di public/js/app.js) menampilkan 2
      opsi: "Arsipkan Data (Soft Delete)" [Rekomendasi Utama] vs "Hapus
      Permanen (Hard Delete)" — opsi Hard Delete otomatis DIKUNCI/disabled
      kalau pelanggan tsb sudah punya riwayat tagihan (invoice), untuk
      mencegah data finansial hilang.
    - Tab "Data Diarsip" di halaman Pelanggan (?status=archived) menampilkan
      pelanggan yang diarsipkan, lengkap dengan tombol Restore.
    - Endpoint baru: POST /customers/:id/restore, POST /customers/:id/hard-delete.
  BELUM diimplementasikan pada patch ini (lihat "BELUM SELESAI" di bawah):
  Tagihan/Kas, ODP/Cluster, Paket — masih pakai mekanisme delete lama.

  BONUS FIX (di luar brief, ditemukan saat mengaudit Section 4): dua bug
  keamanan data di routes/finance.js — sebelumnya transaksi kas yang statusnya
  sudah APPROVED (bagian resmi jurnal kas) BISA dihapus permanen tanpa guard,
  baik lewat hapus satuan (/cash/:id/delete) maupun hapus massal per-periode
  (/cash/delete-all). Sekarang keduanya memblokir penghapusan transaksi
  APPROVED dan melaporkan jumlah yang di-skip.
